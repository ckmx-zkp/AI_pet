# 03 — xiaozhi-server（小智服务）设计缺口分析

> 依据：`00-AI宠物市场与竞品调研.md`（引用"启示 N"编号）、本仓 `docs/00~07`、`work_dashboard/AI-Pet固件联调看板.md`（S1~S5）。
> 范围：本仓（OTA/激活/会话编排/MCP 路由/智能体运行时）。固件侧、业务后端侧缺口分别见 02、04 文档。
> 调研时间：2026-08-01。现状：v0.9.6 全模块上线、真机首轮对话已通；Epic B/C 全部未开工。

## 1. 项目定位一句话回顾

自建小智兼容会话后台：在自控云上完成设备 OTA/激活与 ASR→LLM→TTS 实时编排，并作为**人设、记忆、情绪在运行时落地的唯一执行层**——业务后端是真源，本仓决定"宠物在每一秒表现得像不像一只宠物"。

## 2. 已有设计的市场契合度

- **自建云、数据自主**：对话与记忆资产归属自己，是"长期记忆护城河"（启示 3）的产权前提；对标官方云的动机成立（docs/07 §1.0）。
- **模型链路选型对齐官方云体验**：TTS 与小智官方完全同款（火山·湾湾小何）、ASR 同级、兜底链保证"永不哑"——符合情感连续性要求（设备失声=宠物死亡，比延迟更伤害关系）。
- **人设运行时加载架构正确**：pack 钉扎 kb_version + 缓存降级（docs/03），"真源在业务、本仓只加载"的边界与芙崽五行/星座×MBTI 的可运营性匹配。
- **MCP 眼睛路由**：`self.eye.*` 是 LOVOT/Ropet 眼神系统（启示 5"陪伴不一定是语言"）的低成本实现通道，方向正确。
- **隔离与限额意识**：实时面与 Agent 面隔离（docs/04）符合"陪伴服务不可被后台任务拖垮"的稳态要求。
- **结论**：骨架（接入、链路、边界）与市场方向契合；缺的是"骨架之上的编排"——目前本仓只做"通话管道"，尚未做"宠物"。

## 3. 设计缺口清单

> 优先级：P0 = 不修则当前版本不成立/伤留存；P1 = V0.2~V0.3 必备差异化；P2 = 可排后。

### G1. S1~S5 体验债未清偿，直接伤害"宠物感" —— **P0**

- **缺口**：联调看板 S1~S5（误唤醒开场白每次误触都"主动说话"、休息只闭眼不挂断继续 ASR、无语音超时 120s 过长、采样率 16000 vs 24000 重采样告警、MCP 眼睛全量路由未复核完）全部待执行。
- **市场依据**：启示 2（确定性故障感=自动化不是陪伴）；启示 4（设备行为像故障，用户立刻把它归类为"玩具/助手"，期待崩塌）。行业 35% 退货率里大量是这类"体感 bug"。
- **影响**：联调期每一次误唤醒开口、每一次闭眼后还在听，都在训练用户"这玩意不灵"；先于任何新功能消耗信任。
- **建议方向**：按看板 S1~S5 逐条执行（S1 智控台关 greeting；S2 休息意图联动退出挂断；S3 与产品确认后改 20–45s；S4 对齐 24000；S5 按 docs/04 核对五个工具只路由）。**排期放在 Epic B/C 之前。**

### G2. Epic B/C 未开工：人设与记忆是纸面差异化 —— **P0**

- **缺口**：B1~B4（拉 persona_pack/缓存降级/开场 emotion/盲测）、C1~C3（chat/events 旁路/Memory MCP/延迟回归）无一勾选；当前会话跑的是薄人设，旁路转写和长期记忆完全没接。
- **市场依据**：启示 3（记忆是护城河）；调研 §4 已把"人设体系+可审计记忆"列为已覆盖项——但那只在 backend 侧成立，运行时不通等于没有。
- **影响**：V0.2 完成定义全部落空；与官方云相比的两项"超越"（docs/07 §1.1）在真机上体验不到。
- **建议方向**：按 docs/05 接口先打通 B1+C1 最小环（拉 pack→合并 system→旁路 events），再补降级与 Memory MCP；验收用 docs/03、05 的既有 checkbox。

### G3. 无主动会话能力：宠物永远不会"先开口" —— **P1**

- **缺口**：纯唤醒词触发，服务端无→设备的主动下推通道，也无"什么时候该开口"的时机策略。调研 §4 已列为明确缺口。
- **市场依据**：启示 1（被需要感>功能完整性，LOVOT 主动性是留存第一变量）；启示 5。
- **影响**：关系方向永远单向——只有用户找宠物，没有宠物找用户；"它需要我"无从谈起。
- **建议方向**：分两步。① 通道：评估上游 WS 会话内服务端主动发起 TTS 的可行性（不动协议层，优先利用既有连接与 MCP/通知机制）；② 策略：时机决策放业务侧（心情/事件驱动），本仓只做执行与频控（防打扰上限）。V0.3 立项。

### G4. 无"无声陪伴"编排：对话即全部 —— **P1**

- **缺口**：idle 状态无任何行为设计——无环境声、无呼吸感、无随机小动作；不说话时宠物等于关机。
- **市场依据**：启示 5（Ropet"聊天≠陪伴"，无声在场是更深层连接）；EMO 的自主行为=生命感。
- **影响**：在场感为零，设备沦为"按下才应答的语音盒子"，正中助手化陷阱（启示 4）。
- **建议方向**：本仓负责 idle 编排策略与心跳（多久触发一次小动作/短音），动作执行走 MCP 路由固件工具（眨眼/转动/灯带 V0.3）；注意与 S3 会话超时策略联动——idle 编排应发生在低功耗监听态而非全程挂 WS。

### G5. 防助手化只有 persona_pack taboo，运行时无兜底 —— **P1**

- **缺口**：taboo 字段是静态提示词，LLM 漂移时无任何运行时防线：用户问天气/问穿搭时缺拒答编排与人设一致性兜底。
- **市场依据**：启示 4（Ropet CEO：一旦被当语音助手，期待立刻崩塌）。
- **影响**：免费档 GLM 人设跟随能力本就弱于商用模型，漂移概率更高；一次"好的，为您查询天气"就击穿宠物人设。
- **建议方向**：三层防线——① pack 内固化"宠物化拒答"模板（不知道的事用人设口吻承认不知道）；② 本仓加轻量意图护栏：命中通用助手意图（天气/新闻/翻译等）时注入拒答改写或降级话术；③ 旁路日志标记漂移样本回流给 PersonaCompiler 迭代 taboo。

### G6. 记忆调用是被动工具，缺"主动提起"钩子 —— **P1**

- **缺口**：memory.search 由 LLM 自行决定调不调；没有"开场主动召回"编排（如记得今天是你生日、上次聊到考试）。
- **市场依据**：启示 3（记忆要"主动召回"而非存在库里）；芙崽 EchoChain 的"主动提起"是已被市场验证的对标项。
- **影响**：记忆护城河只蓄水不放水；用户感知不到"它记得我"，离开成本建立不起来。
- **建议方向**：B1 拉 pack 时业务侧随 pack 下发 `recall_hooks`（本日生日/纪念/未结话题），本仓在开场白合成时注入；改造量小、收益直接，建议并入 Epic B 而非另立 Epic。

### G7. 情绪无跨会话连续性 —— **P1**

- **缺口**：`default_emotion` 只在开场一次性生效，无"上次聊得不开心→这次有点低落"的状态延续；会话结束无情绪回写。
- **市场依据**：启示 2、3（Moflin 冷落会低落、LOVOT 会等待——情绪记忆是"它活着"的核心证据）。
- **影响**：每次开机都是"新生儿"，长期相处无积累感。
- **建议方向**：会话结束时本仓在 `sessions/{id}/end` 旁路中带情绪摘要（业务侧已有该端点预留，docs/05）；开场 emotion 由 pack 从"静态默认"升级为"业务计算的开场情绪"，本仓只执行 MCP 调用。

### G8. 声纹能力未利用 —— **P2**

- **缺口**：上游支持声纹识别，未启用；无法区分家庭成员→不同记忆空间与不同亲密度。
- **市场依据**：启示 3 的延伸（记忆按"人"隔离才可信）；Onorato"已经认识你"的家庭场景。
- **影响**：多人共用一台设备时记忆串味，"它记得我"变成"它记得这个屋子的谁"。
- **建议方向**：V0.3+ 评估上游声纹模块开启成本；`chat/events` payload 增加 speaker 标识字段，业务侧记忆空间按 device_id+speaker 分桶。先做字段预留，识别后补。

### G9. 行为完全确定性，无养成/随机性注入点 —— **P2**

- **缺口**：服务端编排无任何随机性/个体演化机制；同一输入同一输出。
- **市场依据**：启示 2（用户投诉第一名是"被摸透了"；Moflin 400 万种性格组合）。
- **影响**：长期留存变量缺失。
- **建议方向**：不做本仓自研；在 idle 编排（G4）与开场情绪（G7）中预留"业务侧下发的随机种子/演化参数"透传通道即可。

### G10. 陪伴北极星指标无埋点 —— **P1**

- **缺口**：调研 §4 指出"周有效陪伴互动次数 × 可召回记忆条数"无度量；本仓掌握全部会话事件却未输出任何统计端点。
- **市场依据**：退货率/次月留存是行业生死线（调研 §1），没有埋点等于盲飞。
- **影响**：G3~G7 上线后无法验证收益，也无法发现流失前兆。
- **建议方向**：C1 旁路事件已含 session_id/role/ts，补会话时长、唤醒来源（人唤醒/误触/主动）、memory.search 命中次数三类字段；统计聚合放业务侧，本仓只保证字段齐全。

### G11. 工程现实债：降级未演练、限额缺失、明文密钥 —— **P0/P1**

- **缺口**：① docs/05 失败策略（缓存降级/重试队列/记忆缺失继续对话）只在文档，未经真实故障演练；② Epic D1 Docker CPU/内存限额未做，Agent 面可抢实时面资源（docs/04 验收项悬空）；③ 智谱/Kimi 密钥存本地 `api.txt` 明文且未入库（docs/07 附录自认），与"密钥不进文档不进 git"纪律仅一线之隔；④ GLM 免费档有 QPS 限速，多设备并发时无容量结论。
- **市场依据**：启示 3 的反面——情感连续性依赖服务稳态；一次业务宕机导致人设丢失，就是宠物"失忆"。
- **影响**：业务后端抖动直接传导为真机人设丢失/记忆缺失；密钥泄露可致账单与数据事故。
- **建议方向**：D 系提前——拔网线演练三类降级并截图存档；D1 限额与 G2 同批落地；`api.txt` 迁入服务器环境变量/密管并删除明文文件（同时排查是否被 git 跟踪）；LLM 切换 qwen-flash/豆包按 docs/07 §1.2 在内测演示前完成。

## 4. 不建议做的事（既有边界重申）

- **不自建星座 KB / 不做记忆 CRUD 真源 / 不实现 PersonaCompiler**（docs/00 硬边界）：本仓只做运行时加载与执行。
- **不碰协议层**：OTA/WS/MCP 协议保持上游兼容，主动下推等需求优先在协议既有机制内实现，避免与上游 bump（D3）冲突。
- **不自研 ASR/TTS/LLM 托管**（docs/01 非目标）：外部 API + 兜底链已验证可行。
- **不在通话中做全量 KB 检索改写人设**（docs/03 R8）。
- **不把浏览器 Agent 放进实时语音路径**（docs/01、04）。
- **不做过早的声纹/行为控制器深集成**：字段预留先行，识别与执行后补（G8、docs/04 V1.0+）。
