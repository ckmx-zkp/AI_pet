# 开发逻辑与阶段总表

## 为什么这个顺序

大板已经在手里。未提交固件里眼睛、灯、相机、跟随都写过了，缺的是烧上去看见，以及「一句话同时动身体」。

记忆优化（向量、衰减、情景/语义）加在 **backend 召回**，固件只多一个「应用 embodiment hint」的窄口。把向量检索搬进 S3，既没内存也破坏现有边界。

```
P0 到板看见
 → P1 同轮眼+灯（体验核心）
 → P2 记忆改默认情
 → P3 云端召回升级（固件无感）
 → P4 一个协调器仲裁优先级
```

## 阶段总表

| 阶段 | 目标 | 完成标准 | 不做什么 |
|------|------|----------|----------|
| **P0 到板** | 把未提交固件烧上大板 | 眼 / 灯 / 拍照 / K230 跟随目视；舵机跟脸 | 不上 4G、不改契约 |
| **P1 同轮联动** | 对话内容驱动身体 | 开心时眼和灯一起变；说话眨眼加快保持现状 | 不解析整段 TTS |
| **P2 记忆→身体** | persona / C5 带 embodiment | 连接后 `default_emotion` + 星座灯；唤醒可用记忆改默认情 | 固件不调 `memory.search` |
| **P3 云端记忆** | 业界召回接到现有三工具 | hybrid 检索、`kind`、检索期衰减 | 不改 Memory MCP 工具名 |
| **P4 行为聚合** | 一个协调器 | 休息闭眼 > 本轮 MCP > 记忆默认情 > K230 跟随 > 自动眨眼 | 不重做 P4 7B 板；不提前空建 `main/pet/` |

## 有板第一周（建议）

1. 烧当前 S3 固件，按 [[03-P0-大板到板验收]] 打勾（舵机/触摸未接则那几项记「硬件未接」）。
2. `eye.set_emotion` 内部同步 LED（见 [[04-P1-眼睛RGB与对话联动]]）— **2026-09-20 COM28 真机已过。**
3. 真机说一句偏好，走通 `memory.search` → 同轮改脸和灯（见 [[06-记忆优化如何接到嵌入式]]）。依赖 P1 烧录后的话术。
4. 飞线 `PA_EN` 后再听 TTS。

契约要动（embodiment 字段、`memory.kind`）时：先改 `ai-pet-backend/docs/06-HTTP-API规范.md` 和 `xiaozhi-server/docs/05-与业务后端集成接口.md`，进度日志写「契约已变更」。
