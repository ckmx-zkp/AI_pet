# P2–P4 记忆到行为层

在 P1 同轮联动稳定之后再做。固件仍然不存记忆。

## P2 记忆 → 身体

云端已经能想起事实，缺的是「想起之后身体有默认姿态」。

建议在 C5 或 companion `GET .../context` 增加很小的 **embodiment hint**（先改契约再写代码）：

```json
{
  "emotion": "happy",
  "led_mode": "zodiac:leo",
  "gaze": "center"
}
```

规则：

- 语义记忆（稳定偏好、星座、关系）→ 开机 / 连接后的默认情和灯。
- 情景记忆（昨天吵架、今天约定）→ 唤醒时短暂表情，几秒后回到默认。
- 过期 `companion_followups` 不再点灯。
- 固件只提供 `ApplyEmbodiment(hint)`，由小智在拉到 pack / C5 后下发一次 MCP 或沿用已有 `default_emotion` 映射。

连接后的落地顺序：

1. 小智拉 `persona_pack`（已有，300 秒刷新）。
2. 把 `default_emotion`、`blink_profile` 应用到 S3。
3. 唤醒时 C5 若带 embodiment，覆盖本次会话默认，不写回固件 NVS。

## P3 云端记忆升级

见 [[06-记忆优化如何接到嵌入式]]。工具名保持：

- `memory.search`
- `memory.add`
- `memory.forget`

固件无感。必须先有真机一次 `memory.search` 基线（看板 X1），再上向量，否则无法对比 ILIKE。

## P4 行为协调器

这时才立项看板 F5 的行为层，不要提前空建 `main/pet/`。

建议一个 `BehaviorCoordinator`，输入四路，输出眼 / 灯 / 舵机：

| 优先级（高→低） | 来源 | 例子 |
|-----------------|------|------|
| 1 | 休息 / 闭眼 / 安全 | `self.eye.close`、4G 保持关 |
| 2 | 本轮 MCP | 用户刚说的情绪 |
| 3 | 记忆默认情 | P2 hint |
| 4 | K230 本地跟随 | 转头转眼 |
| 5 | 自动眨眼 / idle | `auto_idle_` |

仲裁原则：MCP 本轮占用时，K230 只动舵机、不抢表情；休息时跟随暂停。
