# 记忆优化如何接到嵌入式

对照网上常见方案（Mem0、MemoryBank、MemGPT/Letta、Zep）和本仓库已有能力。  
**优化发生在 backend / 小智；嵌入式只负责把「想起什么」做成表情和灯。**

## 现有记忆链路（不要推翻）

```
对话 LLM 按需 memory.search
  → 小智 Memory MCP 客户端
  → backend /mcp（ILIKE + tags，limit 1–20）
  → PostgreSQL memories

唤醒 C5：最多 3 条 active + 日摘要（短，不替代 search）
会话结束 worker：daily_summary / 候选记忆
App / Admin：人工审核 candidate
陪伴六工具：偏好写 candidate，约定进 companion_followups
```

固件 MCP 只有眼 / 灯 / 舵机 / 相机。保持这样。

## 业界方向怎么落

| 网上做法 | 仓库现状 | 接到大板 | 不要做 |
|----------|----------|----------|--------|
| 情景 vs 语义 | 一表全装，无 `kind` | 语义 → 默认情/星座灯；情景 → 唤醒闪一下 | Flash 存对话 |
| 工具分页（MemGPT） | 已按需 search + C5 | search 命中偏好后同轮 eye+led | `self.memory.*` |
| 抽取 ADD/UPDATE | add 只 candidate；worker 可自动 active | 先统一晋升，再让画像改 `blink_profile` | 每轮都 add |
| 检索期衰减 0.3–1.5× | forget 只归档 | backend 加权；过期约定不点灯 | 设备端艾宾浩斯 |
| BM25 + 向量 | `embedding` 列空着 | 只改 search 实现，工具名不变 | S3 跑 kmodel 当记忆 |
| 睡眠巩固 | session/end → worker | 巩固结果写入 `default_emotion`，下次开机生效 | 空闲设备自己总结（E11 冻结） |

## 推荐接入顺序

1. **真机基线**：说一件已写入的事实，日志里看到 `memory.search`，回复用上它。
2. **身体闭环**：同一轮 `eye` + `led`（依赖 [[04-P1-眼睛RGB与对话联动]]）。
3. **统一写入**：MCP add、worker 自动通过、companion feedback 三条晋升规则写进 `docs/04` / `docs/06`。
4. **加 `kind`**：`semantic` / `episodic` / `preference`（契约先行）。
5. **检索衰减**：软加权，不硬删。
6. **embedding + hybrid**：列已经预留 1536 维；先写入再 HNSW。

## 验收句（锁 P1+P2）

> 主人说「我喜欢黄色」→ 真机 `memory.search` 命中 → 同一轮眼睛 happy、灯偏黄。  
> 下次唤醒，C5 带上这条，默认情不再是冷白。

## 和陪伴六工具的边界

- `interaction_feedback` → Memory candidate，批准后才能进默认灯色。
- `followup_plan` → `companion_followups`，到期可以短暂改表情，不是长期记忆。
- `context_search` 的 180 秒证据缓存是会话临时物，不要点灯当人格。
- 朋友云桥 14 工具是隔离账号，不要接到宠物大板。
